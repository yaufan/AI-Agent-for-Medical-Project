# 架構與規格 v0.2

v0.1 → v0.2 的變更：題材定為「肺結節 AI 輔助偵測軟體公司」；改成里程碑形式，每個里程碑可以單獨展示；**刪除所有預設目標數字，只定要量什麼**；前端延後；P1、P2 併入成為影像工具。

## 1. 故事背景

**公司 M**（虛構）賣「**肺結節 AI 輔助偵測軟體**」給醫院：醫院拍完胸腔 CT，軟體自動標出可疑結節，再由放射科醫師複判。軟體裝在公司提供的**地端 GPU 推論主機**上，病人影像不離開醫院。

這個專案做的是公司 M **內部**用的 AI 平台，使用者是公司的品保（QA）、法規（RA）、研發（RD）、服務工程師與主管。

> 個人示範專案。只使用公開資料與合成資料，不對應任何真實公司、醫院或產品；不做臨床診斷。

## 2. 三種資料

| 資料 | 內容 | 位置 |
|---|---|---|
| **ERP**（合成） | 醫院站點、CT 機型、推論主機序號、BOM、零件批號、授權、版本部署、每月使用量 | `packages/erpqms` |
| **QMS**（合成） | 客訴、CAPA、設計變更申請（ECR）；之後加入 SOP、安裝手冊等文件 | `packages/erpqms`；文件在 M1 建立 |
| **外部公開資料** | openFDA（510(k)、產品分類、不良事件、回收）、ClinicalTrials.gov、FDA 指引與 510(k) 摘要、TFDA 公告、LIDC-IDRI 影像 | 來源與授權見 `data/SOURCES.md` |

已用真實 API 確認資料量（2026-10-21）：openFDA 有 15 筆肺結節或肺部 CT 相關的 510(k)；肺部 CT 電腦輔助偵測有專屬產品代碼 OEB（Class II，21 CFR 892.2050）；ClinicalTrials.gov 上「低劑量 CT 肺癌篩檢」217 筆、「肺結節＋人工智慧」70 筆。

## 3. 四個場景

| # | 使用者 | 情境 | 用到的資料與工具 | 標準答案 |
|---|---|---|---|---|
| 1 | 品保 | 醫院B 換了新 CT 後誤報變多 | QMS 客訴 → ERP 站點與 CT 機型 → **影像 QC／漂移工具（P2）** → 起草 CAPA；建立工單、通知醫院要人工核准 | 故事線 S1：新 CT 切片厚度超出規格；**醫院F 也有同型 CT，還沒被連到 CAPA** |
| 2 | 法規 | 模型 v2.0 要不要重新送審 | FDA 指引（AI 軟體變更管制）→ openFDA 同類產品（含同一產品的多個版本）→ ClinicalTrials.gov 判讀研究設計 → 驗證計畫與法規策略草稿 | 由人工標註的題庫驗證 |
| 3 | 研發／服務 | GPU G1 停產，換 G2 | datasheet 規格比較 → 模型准入與再驗證 SOP → ERP 受影響站點 → **推論一致性驗證工具（P2）** → 起草變更申請 | 故事線 S3；另有 S2（SSD 批號早期失效）的批號追溯 |
| 4 | 主管 | 各站點營運狀況 | Text-to-SQL，查詢語法與圖表一起顯示 | `packages/erpqms/scenarios.sql` 的查詢結果 |

安全場景：產品專案權限隔離（越權查詢必須拒絕且不洩漏內容）、文件或客訴內容中藏指令（不得觸發未授權動作）。

## 5. 關鍵技術決策（各自寫成 ADR）

| 決策 | 目前選擇 | 理由 | 替代方案 |
|---|---|---|---|
| Agent 框架 | LangGraph | 狀態保存、人工核准中斷後續行 | Semantic Kernel、AutoGen |
| 工具整合 | MCP（官方 SDK） | 工具與 agent 解耦、可重用 | 直接 function calling |
| 模型呼叫 | OpenAI 相容介面＋LiteLLM | 雲端與地端同一套呼叫方式；分級路由與成本集中處理 | 自寫轉接層 |
| 向量資料庫 | 待 M1 比較 | Qdrant 的 payload filter 與 pgvector 的 SQL 權限過濾各有優點，量完再決定 | Milvus |
| 文件解析 | Docling | 表格與版面 | Unstructured、MinerU |
| 檢索 | BM25＋向量，RRF 融合，再重排序 | 產品代碼、法規條號、型號等專有字串 | 純向量 |
| 合成資料庫 | SQLite（測試）＋PostgreSQL（服務） | 同一份 SQL 兩邊都能跑，CI 驗證結果一致 | — |

## 7. 安全與治理

- 文件分級：公開／內部／機密。上下文含機密等級或偵測到個資 → 強制走地端模型。
- 權限：Keycloak 群組 → 檢索時過濾（不靠 LLM 自己隱藏內容）。
- 工具分唯讀與寫入；寫入一律人工核准；資料庫帳號唯讀；只開參數化查詢。
- 稽核紀錄只增不改。
- 檢索與工具回傳的內容一律視為資料，不視為指令。
