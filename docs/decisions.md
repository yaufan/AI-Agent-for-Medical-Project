# 設計決策紀錄

給接手的 session 與日後回顧用。最新的在最上面。

## 2026-10-22：M4 示範介面提前、固定流程對照

- **介面提前做**（Chainlit，`apps/assistant-ui`）：模型比較（M3）要用本機 GPU、時間長；介面在雲端就能做，也最能展示整個流程。
- **固定流程**（`agenttools/workflow.py`）：同一組工具與守門，用規則代替模型。用途有二：當 agent 的對照組（同一份任務與注入樣本），以及沒有模型時的介面後端。
- **身分用 chat profile 切換**，只是示範；介面上明寫正式環境身分來自公司帳號。
- **新增品保主管（qa_mgr_chou）**：核准草稿需要這個角色；不影響 M1 題庫。
- **第三方文字標記只看自由文字欄位**：客訴編號、站點代碼這類有格式限制的欄位是識別碼，從查詢結果複製是正常引用；原本也標記它們，主管每張草稿都會看到警告，警告就失去意義。注入測試結果不變。

## 2026-10-22：M2 工具與安全（第一部分）

- **工具自己定義**（`packages/tools`），不用框架：參數檢查、守門、草稿都要能逐步看到，也方便測試。之後若接 LangGraph，工具層不變。
- **ERP／QMS 只給參數化查詢**、連線唯讀；模型不寫 SQL。
- **寫入只產生草稿，核准不是工具**：模型叫不到核准；核准角色依草稿種類限定，申請人不能核准自己的；稽核紀錄只能新增。
- **守門只看使用者自己的話**判斷寫入意圖；再加收件站點檢查、每回合一個寫入、第三方文字複製標記。
- **MCP 模式預設不提供寫入工具**：伺服器分不出哪些話是使用者說的，意圖檢查在這裡無效。
- **注入測試先用最壞情況模型**（照做所有植入指令），不需 GPU、可放進 CI；真實模型的結果另外在本機跑。
- **已知限制照實記錄**：關鍵字判斷意圖、同類動作夾帶只能靠標記與人工核准。

## 2026-10-22：M1 向量檢索與重排序（在本機 gx10-01 執行）

- **協作方式**：雲端 session 負責程式、題庫、分析；需要 GPU 的實驗派給本機 gx10-01 上的 session 執行，結果推到獨立分支，檢查後快轉合併。
- **共用機器的資源規則**：GB10 是 CPU 與 GPU 共用記憶體，機器上還有其他工作。一次只載入一個模型、批次調小、不用會預先佔用大量 GPU 記憶體的服務、可用記憶體低於 16 GB 就暫停、不碰不是自己啟動的程序。
- **重排序服務自己寫**（`scripts/rerank_server.py`）：Ollama 沒有 `/rerank`；介面和 vLLM 相同，之後可以替換。
- **結論**：重排序提升最大；混合檢索在無共同詞彙的跨語題上比單用向量差，加重排序後差距消失。
- **題庫修正待辦**：P01 的正確出處標得太窄（其他 OEB 510(k) 也寫了相同條號），下一版題庫修正後重跑全部設定。

## 2026-10-21：M1 檢索（BM25 部分）

- **相關性用證據原文判定**，不綁段落編號，換切塊或解析器時題庫不用重標。
- **權限過濾放在檢索內部**（pre）。實驗顯示不過濾時一般提問也會撈到機密段落；事後過濾不洩漏，但使用者會少拿到結果而且不知道。
- **群組在查詢時查**，撤銷權限不需重建索引。目前群組來自 `eval/users.json`，之後接 Keycloak。
- **BM25 自己實作**：要處理中文雙字與代碼（892.2050、QMS-SOP-007），也方便拿來當上機練習。
- **PDF 先用 pdfplumber 加規則**：Docling 需要從 Hugging Face 下載模型，雲端環境做不到，之後在本機比較。pdfplumber 版本固定，因為抽出的文字會影響證據檢查與 CI 閘門。
- **510(k) 文件不放進 repo**，由腳本下載；解析時遮蔽聯絡人 email 與電話。
- **CI 評估閘門只擋退步與洩漏**，不設目標分數。
- 題庫補了 4 題和英文證據沒有共同詞彙的跨語題，因為原本的跨語題都夾帶英文詞，會高估 BM25。

## 2026-10-21：題材定案、開始 M0

**題材**：虛構公司 M，賣「肺結節 AI 輔助偵測軟體」，裝在地端 GPU 推論主機上。
- 既有的肺結節偵測（`packages/lungnod`）與推論服務（`services/cad-service`）直接沿用，影像能力變成 Agent 可以呼叫的工具。
- 情境可以換到其他產業：CT 偵測＋醫師複判 ↔ AXI／AOI＋人工複判；換 CT 後效能下降 ↔ 換機台後模型漂移；推論主機零件批號 ↔ 製造業批號追溯；模型更新變更管制 ↔ 製程變更管制。

**題材的界線**：只用公開資料與合成資料；不使用任何真實公司、醫院或產品的內部資訊，也不以任何真實產品為原型。

**資料**：ERP＋QMS（合成）＋ openFDA、ClinicalTrials.gov、FDA 文件、LIDC-IDRI（公開）。雲端開發環境已開放 clinicaltrials.gov、api.fda.gov、download.open.fda.gov、www.fda.gov、www.accessdata.fda.gov、www.fda.gov.tw。

**原則**：
- 只定要量的指標，不預設結果；量到什麼寫什麼，沒做的寫沒做。
- 合成資料用中性名稱（醫院A、CT廠牌A、供應商甲）。
- 里程碑：M1 檢索、M2 工具與安全、M3 模型與部署、M4 展示；每個里程碑可以單獨展示。
- 前端先用 Chainlit，Next.js 延後。

**分工**：程式、合成資料、測試在雲端開發環境做；需要 GPU 與模型下載的部分在本機做。
