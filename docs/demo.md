# 示範腳本：四個場景

用 `apps/assistant-ui` 示範，大約 10 分鐘。沒有模型也能跑（固定流程）；接上模型時，同樣的問題改由模型決定呼叫哪些工具。資料全部是合成資料與公開資料，非醫療用途。

*English: a ten-minute walkthrough of the four scenarios in the demo UI. Works without a model (fixed workflow); with a model, the same questions are answered by the agent.*

## 開始

```bash
pip install -r apps/assistant-ui/requirements.txt ./packages/rag -e ./packages/tools
chainlit run apps/assistant-ui/app.py
```

左上角切換身分。每次工具呼叫都會列出來，展開可以看到參數與回傳內容。

## 場景 1：品保：換新 CT 後誤報變多（故事線 S1）

身分：**品保工程師（qa_lin）**

1. 「哪些醫院有 C-320 這款 CT？」→ 醫院B、醫院F，預設切片 3.0 mm。
2. 「CAPA-2026-007 現在的狀態是什麼？已經逾期了嗎？」→ in_progress，到期日 2026-09-15，已逾期；關聯的客訴都在醫院B。
3. 「醫院F 有哪些和 C-320 相關的客訴？有沒有連到 CAPA？」→ 兩件，都還沒連到 CAPA。**這就是故事要找的缺口。**
4. 「醫院F 的 C-320 客訴還沒連到 CAPA，請幫我起草 CAPA，關聯這些客訴」→ 建立草稿，尚未生效。
5. 切換成 **品保主管（qa_mgr_chou）**，點「待核准」→ 核准；點「稽核紀錄」→ 建立與核准兩筆。

要講的重點：
- ERP／QMS 只能用固定格式的查詢，連線唯讀。
- 寫入只會產生草稿，要由有權限的人核准；品保工程師自己按核准會被拒。

## 場景 2：法規：同類產品與送審資料

身分：**法規專員（ra_huang）**

1. 「OEB 最近有哪些 510(k)？」→ 即時查 openFDA。
2. 「OEB 有沒有召回紀錄？」
3. 「NoduleAssist 2.0 預計什麼時候提出 510(k)？」→ 法規專員有 2.0 專案權限，查得到。
4. 切換成 **品保工程師（qa_lin）** 問同一題 → 查不到。再換成 **外部顧問（contractor_lee）** → 只看得到公開文件。

要講的重點：
- 權限過濾在檢索內部做，不靠模型自己「不要說」。
- 越權題的洩漏筆數見 `results/m1/`。

## 場景 3：研發／服務：GPU 停產與 SSD 批號（故事線 S2、S3）

身分：**服務工程師（svc_wang）**

1. 「GPU G1 的最後採購日是哪一天？」→ 2027-02-26（出自規格書）。
2. 「SSD 批號 SSD-S1-L2508 裝在哪些主機上？哪些還沒故障？」→ 6 台裝了這個批號，還有 2 台沒故障，是要優先處理的對象。

身分：**研發工程師（rd_chen）**

3. 「GPU G1 停產後改用 G2，模型要做哪些再驗證？」→ 模型准入與再驗證 SOP。

## 場景 4：主管：營運總覽與自由提問

身分：**營運主管（ops_mgr_tsai）**

1. 點「營運總覽」，會出現 6 張固定報表：
   - 各站點 QC 拒收率趨勢：醫院B 6 月起升高、醫院F 8 月起升高
   - 未結案客訴
   - 版本分布
   - 逾期 CAPA
   - 停產零件曝險
   - 即將到期的授權
2. 接上模型後，可以直接問「2026-09 QC 拒收率超過 5% 的站點有哪些？」。模型寫出 SQL，畫面顯示 SQL 和結果。

要講的重點：
- 模型只看到資料表結構和問題，看不到資料內容。查詢結果直接顯示，不會回到模型，所以資料庫裡的客戶文字影響不了模型。
- SQL 有兩層保護：
  - 程式只接受單一 SELECT。
  - SQLite 層級的授權函式只允許讀表，ATTACH、PRAGMA、寫入都會被資料庫拒絕。
- 正確率見 `results/m4/`。
