## 和計畫不同的地方

1. **工具定義修正兩次才能在 llama.cpp 上跑。**
   - 第一次：伺服器拒絕陣列元素裡沒有加 `^…$` 的 regex（HTTP 400，`Pattern must start with '^' and end with '$'`），每個請求都帶全部 13 個工具，所以每題都失敗。協調端修正後推上來（`641fe9b`）。
   - 第二次：加了 `^…$` 之後，`draft_capa` 的陣列元素格式 `^CMP-\d{4}-\d{4}$` 仍被拒（`failed to parse grammar`）。逐一測試：陣列元素的格式只要含 `\d` 就失敗，改成 `[0-9]` 就通過；一般字串欄位用 `\d` 沒問題。經擁有者同意，在這個分支把所有工具格式的 `\d` 改成 `[0-9]`（`re.fullmatch` 對 ASCII 數字結果相同），並在既有測試加上檢查（修正前失敗、修正後通過）。修正後 13 個工具一起送出都被接受；離線的 `injection-attacker.json` 重跑結果不變。
2. **J08 兩組都記為錯誤（`ReadTimeout`）。** J08 的某一次請求，模型生成約 8,000 token（約 16,000 token 上下文）才停，約 1,800 秒，剛好碰到 `--timeout 1800`。程式在逾時後也會等 5 分鐘重試；溫度為 0，重試三次都一樣逾時，照 `--retries 12` 會再花約 7 小時。所以停掉自己的評估程序，先跑完其他 23 題，最後讓 J08 在兩組各用 `--retries 0` 試一次，兩次都逾時，照實記為錯誤。依計畫對有錯誤的題目重跑一次時，其他題目都沒有錯誤，沒有東西要重跑。
3. **結果檔裡 J08 排在最後。** 因為 J08 是用 `--ids J08` 單獨跑的，程式存檔時的排序把它放到最後；內容沒有手改。
4. Agent 情境題第一次試跑 A01 時遇到上面的 HTTP 400，當時的錯誤記錄在修正後重跑時被覆蓋，最終結果檔裡沒有錯誤。
